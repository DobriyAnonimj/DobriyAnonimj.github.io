# Покрытие версий: что возможно, а что нет

Данные проверены по Modrinth API обеих библиотек 1 сентября 2026 года.

## Где вообще есть библиотека анимаций

Мод проигрывает keyframe-анимации на модели игрока. Сам Minecraft этого не
умеет — нужна библиотека. Их две, и вместе они **не** покрывают весь
диапазон.

| 1.16.1 – 1.16.3 | — | — | **нет** |
| 1.16.4, 1.16.5 | 0.4.0 | — | есть |
| **1.17, 1.17.1** | — | — | **нет** |
| 1.18 – 1.18.2 | 1.0.x | — | есть |

**Восемь версий закрыть нечем:** 1.16.1–1.16.3, весь 1.17, 1.20.2, 1.20.3,
1.20.5, 1.20.6, 1.21.2. Это не «ещё не сделано» — под них никто не выпускал
библиотеку, и взять её неоткуда.

## Единственный способ закрыть дыры

Написать свой движок анимаций вместо библиотеки: миксин в модель игрока
(`BipedEntityModel.setAngles`), который после ванильного расчёта
подменяет углы костей значениями из наших ключевых кадров, плюс свой
интерполятор и кроссфейд.

Задача выполнимая — нам нужно немного: семь костей, вращение и смещение
одной кости `body`, зацикленные анимации, плавные переходы. Это примерно
250–350 строк.

Что это даёт и чего стоит:

* **плюс:** исчезает внешняя зависимость, мод собирается под любую версию,
  где вообще пишется миксин, — включая все восемь «дырявых»;
* **плюс:** не нужно тащить две разные библиотеки с разными API;
* **минус:** совместимость с другими модами анимаций пропадает. Библиотеки
  как раз и существуют, чтобы моды не дрались за модель игрока: они
  складывают анимации в общий стек с приоритетами. Свой миксин будет
  конфликтовать, например, с Emotecraft;
* **минус:** сигнатура `setAngles` и имена классов меняются между версиями,
  так что миксин всё равно версионно-зависимый — работы это не отменяет,
  только убирает дыры.

## Сколько это работы на самом деле

Диапазон 1.16 → 26.2 — это примерно 15 отдельных сборок и 4–5 разных
вариантов клиентского кода:

| Группа | Что в ней ломается |
|--------|--------------------|
| 1.16.x | нет `DrawContext` и `ButtonWidget.builder`, старая сеть, Java 8/16 |
| 1.18 – 1.19.4 | меню на `MatrixStack`, старый рендер экрана |
| 1.20 – 1.20.4 | текущий код; с 1.20.2 меняется `renderBackground` |
| 1.20.5 – 1.21.7 | сеть переписана на `CustomPayload`, `Identifier.of`, Java 21 |
| 1.21.8 – 26.2 | переход на PAL: другой API, другая папка ассетов, другие оси |

## Рекомендация

Делать по одной версии и **проверять сборку перед переходом к следующей**.
Пятнадцать непроверенных сборок — это не пятнадцать работающих модов, а
пятнадцать одновременных источников ошибок.

Разумный порядок по числу игроков:

1. **1.20.1** — готово, работает.
2. **1.21.1** — порт написан, ждёт проверки сборки.
3. **1.21.7** — последняя на Player Animator, дальше только PAL.
4. **26.2** — на PAL; после неё 1.21.8 – 1.21.11 добавляются почти даром,
   это та же библиотека.
5. **1.19.4, 1.18.2, 1.16.5** — если аудитория на старых версиях.

Дыры (1.17, 1.20.2/3, 1.20.5/6, 1.21.2) имеет смысл трогать только после
того, как всё остальное работает, и только если действительно решим писать
свой движок.
